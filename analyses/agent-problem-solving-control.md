# Agent 问题求解的基础控制：问题表征、信念更新、承诺与验收

> 当前判断：本文把问题表征、信念与证据、行动承诺、验证与验收的显式区分作为一种 Agent 风险控制模型。经典问题求解理论、Agent 架构研究和本仓库的工程观察能说明这种区分为何值得检验，但尚不能证明四个维度必要、完备或普遍优于更轻量的控制。重要产物还需要人类审查；本文暂以理解、控制和限定范围内的决策作为审查条件，完整证据边界见独立分析。

## 1. 问题是什么

Agent 可以生成一条局部合理、执行顺畅的路线，却没有证明自己正在解决正确的问题。本文关注的传播过程是：

```text
过窄的问题表征
→ 同源查询
→ 支持性证据占优
→ 暂定假设成为默认事实
→ 围绕该事实规划和执行
→ 用相同前提自我验收
→ 用户接受
→ 错误进入长期记忆
```

“搜索过早收敛”和“过早承诺导致的认知级联风险”可用于概括这条链，但二者目前都不宜冒充边界统一的单一学术术语。前者是多种搜索与判断失效的组合，后者是连接 Agent、人和工程系统的工程化综合概念。

人类位于传播链的关键位置。若审查只剩下浏览最终答案和点击批准，流畅表达会掩盖问题表征、证据和执行中的相关错误。文档、代码和方案即使通过自动测试，也仍可能在意图、逻辑、取舍、风格或决策含义上不受责任人控制。

## 2. 为什么这是 Agent 的基础问题

问题不发生在某个具体模型或工具层，而贯穿认识与行动：

| 关注点 | 核心问题 | 典型失效 |
|---|---|---|
| 问题表征 | 到底在解决什么 | 把症状、用户措辞或初始诊断当成真实边界 |
| 候选空间 | 还有哪些机制和证据方向 | 只做同义查询，只找表面相似案例 |
| 信念更新 | 哪些解释仍然成立 | 锚定、确认偏误、过早闭合 |
| 行动承诺 | 何时允许把判断变成修改 | 证据不足却提前实施 |
| 结果验收 | 什么足以证明完成 | 执行者用相同前提自证成功 |
| 人类审查 | 谁能理解、修改并决定是否接受 | 审查退化为浏览摘要、批准按钮或风格默认 |
| 经验保留 | 什么可以写入长期记忆 | 保存答案，不保存时态、边界和修订原因 |

这些问题域及其相互约束由本文维护；它们在指令、本轮视图、模型外运行环境、跨轮推进或显式图中的实现位置与时间关系，由[《Agent 运行控制的责任边界》](./from-agent-loops-to-explicit-control-graphs.md)维护。本文不规定具体框架或运行时拓扑。

只提高生成质量无法稳定解决这些问题，因为更强的生成也可能更有说服力地完成一条错误路线。

## 3. 相关概念及边界

### 3.1 任务环境与问题空间

Newell 与 Simon 区分外部世界中的任务环境和求解者构造的问题空间。求解实际发生在问题空间中；表征会决定可见状态、可用操作和停止条件。相关理论来源见第 4 节。

面向工程任务，可以用一组开放问题审查当前表征：

| 关注对象 | 需要回答的问题 |
|---|---|
| 目标 | 要改变什么，什么结果才算成功 |
| 观察 | 哪些事实已经直接观察，来源和时态是什么 |
| 约束 | 权限、资源、接口和不可接受后果是什么 |
| 候选机制 | 至少有哪些机制不同的解释或路径 |
| 未知量 | 哪些争议会改变下一步决定 |
| 可用观察 | 哪些搜索、实验或检查能区分候选机制 |
| 后果 | 错误行动的成本、可逆性和风险是什么 |

这是一组可删减和扩展的审查问题，不是问题表征的数学定义、完备字段集或持久状态 Schema。用户原始描述是构造当前表征的输入，不是表征本身；描述越具体，也可能只是把未经验证的机制隐藏得越深。

### 3.2 查询重构、抽象和类比

查询重构与扩展处理术语不匹配；抽象阶梯和模式抽取把具体问题提升到机制层；类比迁移应对齐因果关系，而非寻找表面相同的故事。结构映射理论强调关系结构及高阶关系的对应；相关认知研究见第 4 节。

这些方法不能替代问题表征。若候选机制仍只有一个，增加同义搜索词可能主要扩大同一条路线的证据量，而没有取得能区分机制的新证据。

#### 动作词不是知识对象

一次实际的仓库结构纠错暴露了另一种表征错误：用户说“调研一个新框架”，Agent 可能把“调研”直接映射为 `research/` 目录，再为它建立专门流程、状态和索引；但被处理的对象仍是视觉模型或框架，它与既有模型、机制和任务的关系并没有因为获取方式是“调研”而改变。

这属于工程观察，目前尚未经过系统实验验证。它与结构映射的要求一致：分类应优先保留对象之间的稳定关系，避免直接复刻句子中的表面词。至少要分开两个问题：

- **对象表征**：这是什么，它在现有体系中与哪些对象同类、依赖或竞争；
- **活动表征**：现在对它做调研、评测、实现、迁移还是复盘。

长期归属主要由对象及其关系决定；活动决定当前采用的证据、流程和输出。只有当活动本身形成了独立、长期、不可被现有对象结构承载的知识对象时，才值得升级为新目录或模块。

#### 权威来源与关系引用

对象与活动分开以后，多个产物仍可能复制同一事实、边界和状态。副本最初一致，不表示以后会同步更新；一旦版本、证据或结论变化，审查者就难以判断哪一处仍然有效。

对准备长期复用的内容，应进一步区分：

- **权威来源**：负责定义事实、版本、证据状态和修订边界；
- **关系引用**：说明该事实怎样被另一个问题、方案或流程使用，不重新维护其定义；
- **案例观察**：保存具体环境中的输入、现象和结果，不能反过来改写通用事实。

“权威”表示维护责任，不表示某个来源垄断真理。相互冲突的主张应保留各自证据和适用范围；关系引用也可以质疑权威条目，但不应悄悄复制并形成第二套事实源。这是近期仓库审校暴露出的工程控制问题，目前尚缺少对不同知识维护结构的系统比较。

### 3.3 CBR、CTA 与 CDM

基于案例的推理以 Retrieve–Reuse–Revise–Retain 为循环，重点是旧经验如何适配、验证和被新案例修订，而非保存“问题—答案”对；相关方法论综述见第 4 节。

认知任务分析中的关键决策法通过对一项具体的非例行事件进行多轮回溯，提取时间线、关键线索、判断点和决策要求。它适合从案例叙述中寻找教程通常遗漏的判断依据，但这些材料由当事人回忆与访谈探针共同产生；不能假定它们完整恢复了客观过程或真实因果轨迹。相关方法及数据质量边界见第 4 节。

### 3.4 差异诊断、证伪与信念修订

差异诊断要求同时维护多个原因；证伪要求说明什么观察会削弱当前解释；信念修订研究新信息与旧信念冲突时如何更新知识。相关理论综述见第 4 节。

它们与“列出多个可能原因”不同：真正的要求是让假设产生不同预测，并优先取得能够区分它们的证据。

#### 首个语义分歧边界

复杂链路的最终结果出现差异时，最终症状通常不能直接指出根因。更有区分力的做法是先冻结输入和接口契约，再比较两条路径中语义相同的中间状态，找到第一个显著分歧的边界，然后只在相邻模块内继续下钻。

语义相同比名称或序号相同更重要。不同实现可能融合、拆分或重排步骤；机械对齐“第 N 层”会制造假差异。输入已经不同，就没有依据先归因后续模块；中间状态一致而最终结果不同，则应优先检查下游解释、选择或验收逻辑。

中间输出、数值相似度和可视化只是定位证据，不能代替任务级或系统级 Oracle。若系统不暴露中间状态，应改用能区分候选机制的黑盒输入和输出实验，并保留无法继续定位的不确定性。第 4 节的程序调试研究表明，在具有自动测试、可比较运行和可访问状态时，逐步缩小通过与失败运行之间的状态差异可以形成因果链并定位从预期状态到错误状态的转变。把这一方法迁移到结构不同的实现时，语义对齐和 Oracle 仍是额外工程判断；它不证明逐层比较在所有系统中成本最优。

### 3.5 人类认知偏差与 Agent 工程失效

锚定、确认偏误和过早闭合等术语来自人类判断研究。第 4 节收录的医学来源是一篇继续教育型综述，它整理临床诊断中的常见偏误和去偏证据，最多支持“人类审查者也可能沿初始解释继续收集支持材料”这一风险类比。它不解释 Agent 的内部因果机制，也不能证明同名现象在模型中具有相同成因或干预方式。

因此，本文只用这些术语标记可观察的判断模式，并把人类审查者的偏误视为竞争性失败来源；不对模型作心理归因，也不把临床去偏方法直接迁移为 Agent 控制。

### 3.6 人类审查：理解、控制与决策

人类审查贯穿问题表征、信念、承诺和验收，但它有自己的责任问题，不能只作为行动批准步骤处理。本文暂把责任人理解重要内容与逻辑、能够修改或拒绝产物，并对限定范围作出明确决定，作为重要产物审查的三项责任条件；它们不是经统一实验验证的通用完成定义。

工具调用前的批准、自动测试和 Agent 自评都可以提供局部控制，不能单独证明责任人理解并接受最终产物。审查深度还应随影响、复杂度、证据缺口和可逆性调整。完整论证见[《Agent 产物的人类审查：理解、控制与决策》](./human-review-of-agent-outputs.md)。

“同一 Agent 的反思不足以独立验收”目前也是结构性推断：生成与自评若共享表征、材料和目标，错误可能相关。它支持增加新鲜证据或不同 Oracle，不支持“反思永远无效”。“首个语义分歧边界”受到程序状态因果链研究的结构支持，但跨实现语义对齐、最终 Oracle 和成本收益仍是工程判断，不是已经证明成本最优的通用算法。

因此，现有材料足以提出一个有来源约束的风险模型，并指导低成本、可逆的控制实验；还不足以证明四维划分的必要性、完备性，或证明一套通用流程能在所有 Agent 任务中提高成功率。

## 5. 竞争性解释

至少需要保留以下解释，避免把所有失败都归因于过早收敛：

1. **能力不足**：模型没有理解关键机制，即使给出正确表征也无法求解；
2. **证据不可得**：正确区分需要的日志、权限或实验条件不存在；
3. **目标不清**：用户和 Agent 对成功标准本就不一致；
4. **成本约束**：系统有意在有限时间和 Token 下使用满意化停止规则；
5. **执行错误**：问题和假设正确，但代码、工具调用或环境操作失败；
6. **验收器错误**：Oracle 自身不可靠或覆盖不足；
7. **记忆污染**：过期状态或用户假设被当成当前事实；
8. **激励错配**：系统更奖励快速给出完整答案，而非保留不确定性；
9. **审查条件不足**：审查者缺少时间、领域能力、原始证据、真实修改权或拒绝权；
10. **审查相关失败**：人和 Agent 共享同一错误表征，人工参与没有带来新的证据或视角。
11. **控制形式化过载**：状态、模板、重复权威声明和审查门本身占用了理解与维护能力，反而掩盖真正需要决定的内容。

这意味着不能把“多搜索”“列更多假设”或“加一个人工批准点”当成统一修复；控制强度必须随歧义、后果、不可逆性和证据缺口变化。

## 6. 当前判断

本文当前采用四个风险检查维度，而不是把它们声明为可靠 Agent 的必要且完备组成：

1. **问题表征**：目标、事实、约束、未知量和替代表征；
2. **信念与证据**：竞争假设、支持与反对证据、未验证假设；
3. **行动承诺**：哪些只是候选，哪些已获准进入行动，以及撤销条件；
4. **验证与验收**：什么新鲜、独立的证据足以接受、拒绝或回滚。

这四项不是四个同类存储、互斥字段或线性工作流阶段。同一观察可以同时影响问题表征和信念，同一验收结果也可能触发承诺撤销；区分的目的，是说明信息在当前决定中扮演什么角色，以及它能授权什么动作。

知识整合、技术验证和任务激活属于不同承诺。信息基线经过审查，表示其结构和证据边界可以在限定范围内使用；它不会自动授权实验、实现、部署或发布，也不表示技术内容已经验证。行动应由真实需求、授权、待区分问题和验收条件触发，不能由文档的完整感触发。

人类审查贯穿四个维度，并在重要承诺与产物发布前形成独立的责任边界。审查者要看到与当前决定相关的问题表征、证据、承诺、验收依据和实际制品，满足理解、控制和决定三项责任条件。系统可以记录审查，不能替审查者承担决定。

检索到的信息只能成为候选证据，不能自动变成当前事实；能够执行某个动作，也不等于已经获得该动作的授权；执行者生成的解释，也不等于独立验收；人类点击批准，也不证明其理解了产物。

在选择目录、工具、Agent 角色或工作流之前，还应先做一次“对象—活动”分离：目录回答内容长期属于什么，流程回答当前怎样处理它。不能仅凭用户使用了“调研”“评测”“部署”“复盘”等词，就创建同名知识域。判断新结构是否必要，至少要检查：去掉动作词后对象是否仍无法归入现有体系；新结构是否表达了新的稳定关系；它是否会与现有索引、状态或证据规则重复。

下一步实验应优先选择能够让竞争机制产生不同预测、并会改变当前决定的观察。在区分能力相近时，再优先低成本、低风险、可逆且失败结果仍提供信息的动作。

这是定性优先序，不是假定信息价值、成本和风险已经能被放进同一个精确效用函数。每项测试至少要说明：它区分哪些假设，各假设预期看到什么，以及任何结果将怎样改变行动或保留的不确定性。

重要产物的理解核验、编辑权和决策范围由独立的[人类审查分析](./human-review-of-agent-outputs.md)展开。

## 7. 适用边界与反例

- 目标清楚、改动可逆且已有确定性测试的简单任务，不需要完整假设账本；显式状态、模板和审查门本身也有理解与维护成本，应只保留能够改变行动或验收的最小充分控制；
- 探索性写作和创意生成不总有唯一 Oracle，验收应转向约束满足、风格控制和人工选择；
- 独立 Agent 不天然等于独立证据；若共享表征、材料和评判标准，多 Agent 仍可能相关失败；
- 保留过多假设会产生分析瘫痪，候选集合应由可观察预测和风险约束；
- 外部 Oracle 也可能错，因此高风险任务需要验证 Oracle 本身；
- “搜索过早收敛”只解释一部分失败，不能替代能力、数据、执行、权限和目标诊断；
- 人工审查也会受偏见、疲劳、能力和证据条件限制；审查强度应随影响调整，不能用形式上的人工参与替代独立判断；

可能推翻或显著削弱本文判断的证据包括：在控制任务难度和成本后，显式区分这些责任维度以及加入具备理解、控制和决策条件的人类审查，没有降低错误承诺或虚假完成，反而稳定降低真实任务成功率。

## 8. 对日常 Agent 使用的意义

日常使用不需要先建设复杂平台，可以先改变关键承诺点：

1. 在解决前区分目标、观察事实和用户当前诊断；
2. 遇到案例描述时，追问发生了什么、当时怎样解释、什么纠正或新证据改变了判断、结果如何验证；无法定位过程制品时，把内容保留为当事人报告而非事实或通用原则；
3. 在选目录、工具或流程前区分“对象是什么”和“现在对它做什么”，并明确谁负责维护事实、谁只表达引用关系；
4. 对高歧义问题保留至少一个机制不同的替代解释；
5. 搜索时覆盖机制、上下游、原始来源和反证，而非只改写原句；
6. 把知识整合、技术验证和任务激活当作不同承诺；修改前说明该动作能区分什么、不能区分什么；
7. 高影响动作必须给出授权边界、剩余不确定性和回滚条件；
8. 复杂链路先锁定输入和接口，定位首个语义分歧边界；再用新鲜输出、测试、日志和实际制品验收，不以 Agent 自述或单一相似度为证；
9. 对重要产物使用[人类审查责任条件](./human-review-of-agent-outputs.md)，确认责任人理解关键逻辑、拥有真实编辑权，并对限定范围作出明确决定；
10. 写入长期记忆时区分偏好、假设、事实、决策、历史状态和争议。

这些是控制原则，不是必须固化为若干 Skill 或若干角色。只有当重复失败证明某一步需要机器检查时，才值得产品化。人类责任也不能通过增加一个名为 Reviewer 的 Agent 来替代。

## 9. 待区分的问题

| 决策对象 | 竞争解释 | 足以改变判断的证据 |
|---|---|---|
| 问题表征 | 失败来自错误表征，或只是模型能力不足、评价器共享偏差 | 对同一任务使用机制不同的表征，由领域事实、任务结果或独立 Oracle 比较错误定位与成功率 |
| 搜索停止 | 更多反证能降低错误承诺，或额外搜索只增加成本和噪声 | 在固定预算梯度下测量新增证据的边际错误降低、延迟和无效分支数量 |
| 验收独立性 | 换一个模型或角色已经足够，或必须改变数据、Oracle 与失败路径 | 分别消融生成器、材料、评价器和验证环境的共享程度，比较虚假通过率 |
| 记忆保留 | 结构化状态保留时态和争议，或压缩与覆盖写入制造新的事实漂移 | 在同一跨会话任务上比较原始事件、摘要、类型化状态和制品指针的恢复正确率与维护成本 |
| 显式信念状态 | 高歧义任务从显式候选与承诺中获益，或形式化负担超过收益 | 按任务歧义和风险分层，对照成功率、错误承诺、人工时间、Token 与维护成本 |
| 不确定性展示 | 更多边界信息改善用户校准，或使理解和决定过载 | 在责任人能力与任务难度相近时，测量理解、决策正确率、校准、审查时间和放弃率 |
