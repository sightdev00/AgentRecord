# Agent 问题求解的基础控制：问题表征、信念更新、承诺与验收

> 当前判断：Agent 的基础缺陷不只是“搜索不够深”，而是问题表征、证据搜索、信念更新、行动承诺和结果验收常被压进同一个连续生成过程，缺少相互制约。

## 1. 问题是什么

Agent 经常能生成一条局部合理、执行顺畅的路线，却没有证明自己正在解决正确的问题。典型传播过程是：

```text
过窄的问题表征
→ 同源查询
→ 支持性证据占优
→ 暂定假设成为默认事实
→ 围绕该事实规划和执行
→ 用相同前提自我验收
→ 用户接受
→ 错误进入长期记忆
```

“搜索过早收敛”和“过早承诺导致的认知级联风险”可用于概括这条链，但二者目前都不宜冒充边界统一的单一学术术语。前者是多种搜索与判断失效的组合，后者是连接 Agent、人和工程系统的工程化综合概念。

## 2. 为什么这是 Agent 的基础问题

问题不发生在某个具体模型或工具层，而贯穿认识与行动：

| 控制层 | 核心问题 | 典型失效 |
|---|---|---|
| 问题表征 | 到底在解决什么 | 把症状、用户措辞或初始诊断当成真实边界 |
| 候选空间 | 还有哪些机制和证据方向 | 只做同义查询，只找表面相似案例 |
| 信念更新 | 哪些解释仍然成立 | 锚定、确认偏误、过早闭合 |
| 行动承诺 | 何时允许把判断变成修改 | 证据不足却提前实施 |
| 结果验收 | 什么足以证明完成 | 执行者用相同前提自证成功 |
| 经验保留 | 什么可以写入长期记忆 | 保存答案，不保存时态、边界和修订原因 |

只提高生成质量无法稳定解决这些问题，因为更强的生成也可能更有说服力地完成一条错误路线。

## 3. 相关概念及边界

### 3.1 任务环境与问题空间

Newell 与 Simon 区分外部世界中的任务环境和求解者构造的问题空间。求解实际发生在问题空间中；表征会决定可见状态、可用操作和停止条件。[Human Problem Solving](https://worrydream.com/refs/Simon_1970_-_Human_Problem_Solving%2C_The_State_of_the_Theory_in_1970.pdf)

面向工程任务，可把问题表征近似写为：

\[
P=\langle G,S,C,M,U,O,R\rangle
\]

- \(G\)：目标与成功标准；
- \(S\)：已观察事实；
- \(C\)：约束和授权边界；
- \(M\)：候选机制；
- \(U\)：未知量与争议；
- \(O\)：可执行的观察、搜索和实验；
- \(R\)：错误行动的成本、可逆性和风险。

用户原始描述是构造 \(P\) 的输入，不是 \(P\) 本身。描述越具体，也可能只是把未经验证的机制隐藏得越深。

### 3.2 查询重构、抽象和类比

查询重构与扩展处理术语不匹配；抽象阶梯和模式抽取把具体问题提升到机制层；类比迁移应对齐因果关系，而非寻找表面相同的故事。结构映射理论强调关系结构及高阶关系的对应。[Structure Mapping in Analogy and Similarity](https://cogsci.ucsd.edu/~coulson/203/gentner-markman-97.pdf)

这些方法不能替代问题表征。若候选机制仍只有一个，增加同义搜索词只会扩大同一条路线的证据量。

#### 动作词不是知识对象

一次实际的仓库结构纠错暴露了另一种表征错误：用户说“调研一个新框架”，Agent 可能把“调研”直接映射为 `research/` 目录，再为它建立专门流程、状态和索引；但被处理的对象仍是视觉模型或框架，它与既有模型、机制和任务的关系并没有因为获取方式是“调研”而改变。

这属于工程观察，目前还不是经过系统实验验证的普遍规律。它与结构映射的要求一致：分类应优先保留对象之间的稳定关系，而不是复刻句子中的表面词。至少要分开两个问题：

- **对象表征**：这是什么，它在现有体系中与哪些对象同类、依赖或竞争；
- **活动表征**：现在对它做调研、评测、实现、迁移还是复盘。

长期归属主要由对象及其关系决定；活动决定当前采用的证据、流程和输出。只有当活动本身形成了独立、长期、不可被现有对象结构承载的知识对象时，才值得升级为新目录或模块。

### 3.3 CBR、CTA 与 CDM

基于案例的推理以 Retrieve–Reuse–Revise–Retain 为循环，重点是旧经验如何适配、验证和被新案例修订，而非保存“问题—答案”对。[Case-Based Reasoning](https://www.iiia.csic.es/~enric/papers/AICom.pdf)

认知任务分析和关键决策法关注专家在非例行事件中看到的线索、改变判断的时刻、被放弃的选项及反事实条件。它们适合提取教程通常遗漏的判断依据，但回忆材料仍可能有事后合理化偏差，不能直接等同于客观过程证据。[Critical Decision Method](https://go.gale.com/ps/i.do?id=GALE%7CA21159924&issn=00187208&it=r&linkaccess=abs&p=AONE&sid=googleScholar&sw=w&v=2.1)

### 3.4 差异诊断、证伪与信念修订

差异诊断要求同时维护多个原因；证伪要求说明什么观察会削弱当前解释；信念修订研究新信息与旧信念冲突时如何更新知识。[Logic of Belief Revision](https://plato.stanford.edu/entries/logic-belief-revision/)

它们与“列出多个可能原因”不同：真正的要求是让假设产生不同预测，并优先取得能够区分它们的证据。

### 3.5 人类认知偏差与 Agent 工程失效

Anchoring、confirmation bias、premature closure、automation bias、overreliance 和 cognitive offloading 解释了不同环节的风险。医学诊断文献可提供成熟的结构类比，但这不能证明 LLM 与人脑具有相同内部机制。[Cognitive biases in diagnosis and decision making](https://pmc.ncbi.nlm.nih.gov/articles/PMC8520040/)

因此，本文使用这些概念描述可观察行为和系统结构，不对模型内部心理机制做未经证实的拟人化判断。

## 4. 已有证据

目前的证据强度并不均匀：

- 问题表征限制搜索空间，具有经典问题求解理论基础；
- 锚定、过早闭合等概念在人类判断研究中证据较成熟，但映射到 Agent 主要是结构类比；
- Agent 记忆研究开始区分材料召回与状态承诺，支持“检索不等于事实写入”的工程方向。[AI Agents Need Memory Control Over More Context](https://arxiv.org/html/2601.11653v1)
- 认知 Agent 架构研究表明 reasoning、planning、memory 和 action 的抽象仍不统一，这支持建立更清楚的状态边界，但不直接证明某一控制结构最优。[Cognitive Architectures for Language Agents](https://arxiv.org/html/2309.02427v3)
- “同一 Agent 的反思不足以独立验收”主要来自共享上下文、证据和目标所导致的结构性相关，而不是“反思永远无效”的经验定律。

现有材料足以支持风险模型和设计原则，还不足以证明一套通用流程能在所有 Agent 任务中提高成功率。

## 5. 竞争性解释

至少需要保留以下解释，避免把所有失败都归因于过早收敛：

1. **能力不足**：模型没有理解关键机制，即使给出正确表征也无法求解；
2. **证据不可得**：正确区分需要的日志、权限或实验条件不存在；
3. **目标不清**：用户和 Agent 对成功标准本就不一致；
4. **成本约束**：系统有意在有限时间和 Token 下使用满意化停止规则；
5. **执行错误**：问题和假设正确，但代码、工具调用或环境操作失败；
6. **验收器错误**：Oracle 自身不可靠或覆盖不足；
7. **记忆污染**：过期状态或用户假设被当成当前事实；
8. **激励错配**：系统更奖励快速给出完整答案，而非保留不确定性。

这意味着不能把“多搜索”“列更多假设”当成统一修复；控制强度必须随歧义、后果、不可逆性和证据缺口变化。

## 6. 当前判断

可靠 Agent 至少需要显式区分四类状态：

1. **Problem state**：目标、事实、约束、未知量和替代表征；
2. **Belief state**：竞争假设、支持与反对证据、未验证假设；
3. **Commitment state**：哪些只是候选，哪些已获准进入行动，以及撤销条件；
4. **Verification state**：什么新鲜、独立的证据足以接受、拒绝或回滚。

检索到的信息只能成为候选证据，不能自动变成当前事实；能够执行某个动作，也不等于已经获得该动作的授权；执行者生成的解释，也不等于独立验收。

在选择目录、工具、Agent 角色或工作流之前，还应先做一次“对象—活动”分离：目录回答内容长期属于什么，流程回答当前怎样处理它。不能仅凭用户使用了“调研”“评测”“部署”“复盘”等词，就创建同名知识域。判断新结构是否必要，至少要检查：去掉动作词后对象是否仍无法归入现有体系；新结构是否表达了新的稳定关系；它是否会与现有索引、状态或证据规则重复。

下一步实验应优先按区分能力、成本、风险和可逆性排序：

\[
a^*=\arg\max_a
\frac{\mathbb{E}[\Delta I(H;E\mid a)]}
{Cost(a)+Risk(a)}
\]

工程中不必伪造精确概率。只需明确每项测试能排除哪些假设、不同假设预期看到什么、失败结果是否仍提供信息。

## 7. 适用边界与反例

- 目标清楚、改动可逆且已有确定性测试的简单任务，不需要完整假设账本；
- 探索性写作和创意生成不总有唯一 Oracle，验收应转向约束满足和人工选择；
- 独立 Agent 不天然等于独立证据；若共享表征、材料和评判标准，多 Agent 仍可能相关失败；
- 保留过多假设会产生分析瘫痪，候选集合应由可观察预测和风险约束；
- 外部 Oracle 也可能错，因此高风险任务需要验证 Oracle 本身；
- “搜索过早收敛”只解释一部分失败，不能替代能力、数据、执行、权限和目标诊断。

可能推翻或显著削弱本文判断的证据包括：在控制任务难度和成本后，显式分离这些状态没有降低错误承诺或虚假完成，反而稳定降低真实任务成功率。

## 8. 对日常 Agent 使用的意义

日常使用不需要先建设复杂平台，可以先改变关键承诺点：

1. 在解决前区分目标、观察事实和用户当前诊断；
2. 在选目录、工具或流程前区分“对象是什么”和“现在对它做什么”，不拿动作词代替对象关系；
3. 对高歧义问题保留至少一个机制不同的替代解释；
4. 搜索时覆盖机制、上下游、原始来源和反证，而非只改写原句；
5. 修改前说明该动作能区分什么，不能区分什么；
6. 高影响动作必须给出授权边界、剩余不确定性和回滚条件；
7. 用新鲜输出、测试、日志或人工检查验收，不以 Agent 自述为证；
8. 写入长期记忆时区分偏好、假设、事实、决策、历史状态和争议。

这些是控制原则，不是必须固化为七个 Skill 或七个角色。只有当重复失败证明某一步需要机器检查时，才值得产品化。

## 9. 未解决问题

- 如何测量“问题表征正确性”，而不依赖另一个同样可能偏置的模型？
- 怎样设定停止规则，兼顾反证覆盖与时间、Token 成本？
- 何种独立性足以让验收器真正降低相关失败？
- 如何让记忆保留时态和争议，又不产生维护负担？
- 哪些任务适合显式信念状态，哪些任务只需轻量检查？
- 用户看到多少不确定性最有助于校准，而不会造成认知过载？
