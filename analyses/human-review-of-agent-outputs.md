# Agent 产物的人类审查：理解、控制与决策

> 当前判断：本文暂把理解重要内容、拥有真实修改或拒绝能力、对限定范围作出明确决定，作为重要 Agent 产物审查的三项责任条件。它们描述责任人需要达到的结果，不构成经实验验证的通用必要充分条件，也不规定按钮、顺序或状态机。批准工具调用、浏览摘要或点击“接受”只能证明流程中出现过一个人，不能单独证明这些责任条件成立。

## 1. 问题是什么

Agent 可以生成流畅的文档、通过测试的代码和结构完整的方案，也可以在敏感动作前请求人工批准。然而，这些机制没有自动证明责任人：

- 理解了目标、推理、证据和后果；
- 能够改变内容、结构、实现或叙述风格；
- 知道自己接受了什么、拒绝了什么，以及仍承担什么风险。

若人只看到 Agent 的结论摘要，或者只能批准预先给出的动作，错误的问题表征、选择性证据和相关验收可能被表达质量掩盖。形式上的人工参与会进一步制造“已经有人负责”的错觉。

本文讨论的是准备交付、合并、发布或作为决策依据的 Agent 产物。它不要求人类逐字重做所有机械工作，也不假设人工判断天然正确。

## 2. 为什么这是 Agent 的基础问题

人类审查不是模型生成后的附加润色，而是认识和行动之间的责任边界。

本文与[问题求解控制总论](./agent-problem-solving-control.md)共享问题表征、信念与证据、行动承诺、验证与验收的区分，但只维护其中的人类责任与产物审查边界；运行时授权和控制拓扑不属于本文。

Agent 可能同时担任提案者、证据选择者、解释者和验收者。若责任人只接收同一 Agent 组织后的材料，其判断可能被限制在 Agent 预先选择的问题表征与证据范围内。增加批准按钮没有引入独立证据，也没有改变决定权的实际分配。

不同产物需要审查的对象不同：

| 产物 | 本文责任条件要求责任人控制的对象 |
|---|---|
| 文档 | 核心主张、证据权重、逻辑结构、适用边界和表达 |
| 代码 | 意图、重要数据流、权限、副作用、测试、维护边界和回滚 |
| 方案 | 目标、替代选项、成本分配、不可逆后果和后续决定 |

自动测试、静态检查和策略门可以降低特定错误，但不能独立回答“这是不是责任人愿意承担后果的正确产物”。

## 3. 相关概念及边界

### 3.1 行动批准不等于产物审查

Human-in-the-loop 在 Agent 工具中经常表现为敏感工具调用前的批准或拒绝。以第 4 节记录的 2026-07-27 实现快照为例，运行可以在敏感工具调用前暂停，由人批准或拒绝，并通过运行状态保存和恢复。该页面没有固定版本，因此只作为当时实现边界的证据。

这是重要的行动门控，但它主要回答“是否允许执行这个动作”。完整产物审查还需要回答：

- 动作所依据的问题和事实是否成立；
- 产物的重要逻辑和取舍是否可由责任人重建；
- 责任人是否能修改提案，而非只能接受或拒绝；
- 决定覆盖哪些维度和范围。

因此，工具批准可以是审查的一部分，不能成为审查完成的充分条件。

### 3.2 适当依赖是测量目标

第 4 节收录的适当依赖研究基于既有文献提出一种测量概念：人需要辨别 AI 建议质量，并根据建议正确与否采取相应行动。论文的贡献是概念化和测量框架，不是证明某种解释或审查干预有效。

它支持把审查目标放在判断与行动质量，而不是批准率、人工参与次数或主观信任上；它不能直接证明本文提出的额外理解核验会改善文档、代码或方案质量。

### 3.3 可纠正性与控制

第 4 节收录的 Human-AI interaction 研究从既有研究和行业建议中综合出 18 条指南，并经过多轮评估，包括由 49 名设计从业者针对 20 个 AI 产品进行检验。与本文关系最直接的是支持纠正、说明行为原因、接受细粒度反馈和提供全局控制。

这些结果支持“人需要能够理解并改变系统行为”的交互方向。研究对象是广泛的 AI 产品与设计指南，不是生成式 Agent 产物的责任审查，因此不能直接验证本文的三项责任条件具有通用必要性或充分性。

### 3.4 监督与责任

第 4 节收录的 NIST AI RMF 1.0（2023）把定义并区分人机配置与监督中的角色责任、评估和记录人工监督过程列为治理实践，并指出独立审查可以减轻内部偏差和利益冲突。该框架明确是自愿、非行业特定且与具体用例无关的风险管理资源。

这是治理框架提供的角色、记录和独立性实践，不是某种审查流程提高任务质量的对照实验。它支持责任边界，不能单独决定每类产物需要多深的理解或哪一种界面有效。

## 4. 已有证据及其强度

| 证据与来源 | 认识论角色 | 能支持的判断 | 不能推出的结论 | 版本、时间与适用环境 |
|---|---|---|---|---|
| [OpenAI Agents SDK HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/) | 易变实现证据 | 工具调用可以在执行前暂停，由人批准或拒绝，并保存状态后恢复 | 人已经理解完整产物，或工具批准足以完成产物审查 | 未版本化官方页面；核查于 2026-07-27，接口变化后需重查 |
| [Schemmer 等，2022](https://arxiv.org/abs/2204.06916v1) | 基于文献形成的测量概念 | 适当依赖可由“辨别建议质量”与“据此行动”两个维度描述 | 某种解释、额外理解核验或责任条件已经改善了决策 | arXiv v1；文章说明概念、示例和未来研究，不是统一干预实验 |
| [Amershi 等，2019](https://doi.org/10.1145/3290605.3300233) | 指南综合与多轮评估 | 纠正、行为原因、细粒度反馈和全局控制是跨多类 AI 交互的相关设计要求 | 三项产物审查条件已经在生成式 Agent 文档、代码和方案中验证 | CHI 2019；49 名设计从业者、20 个产品 |

| 本文的理解—控制—决策责任条件 | 工程推断 | 把上述方向与 Agent 提案、执行、验收中的责任边界连接成可检查结构 | 这些条件已是跨任务最优流程，或具有通用必要性与充分性 | 当前只由研究方向、自愿治理指引和工程结构共同支持 |

现有材料足以说明：流程里出现过一个人不能推出审查已经完成；它也足以形成一组可检查的责任条件。现有证据还不足以证明这组条件在所有产物和风险等级上都是必要的、充分的，或都能提高净任务质量。

## 5. 当前判断：三项责任条件

本文用理解、控制和决定检查重要产物是否具备可负责的审查基础。它们描述结果，不规定执行顺序；影响低、可逆且可机械验收时，可以缩减核验深度和留痕，但不能把流程中出现过人等同于这些条件已经成立。

### 5.1 理解重要内容与逻辑

责任人应能脱离 Agent 的结论摘要，用自己的语言准确说明：

- 产物解决什么问题，成功标准和适用边界是什么；
- 核心结构、关键推理链或主要状态转移怎样组成；
- 哪些结论由直接证据支持，哪些属于推断、选择或暂定假设；
- 主要风险、竞争解释、失败条件和剩余未知量是什么；
- 重要副作用、不可逆后果和回滚点在哪里。

“理解”针对重要内容和逻辑，不要求逐字背诵、人工重写或复现每个机械步骤。审查深度应随影响、复杂度和可逆性调整。

### 5.2 控制内容、结构与表达

责任人需要真实的编辑权和否决权：

- 可以修改目标、结构、术语、证据权重和方案取舍；
- 可以要求重构不符合维护边界的代码；
- 可以删除机械对称、空泛总结和虚假完整感；
- 可以查看原始材料、diff、测试、日志和实际制品；
- 可以暂停、回退、拒绝或交给更合适的人判断。

叙述风格属于产物质量的一部分，但风格审查不能代替事实、逻辑、安全和结果审查。

### 5.3 对限定范围作出明确决定

审查应落到可执行结论。决定至少要能区分：接受当前范围、要求修订、拒绝当前方向，或因信息、权限和专业能力不足而转交。具体名称、按钮和记录载体可以随现有工作流变化。

“已阅读”“看起来可以”和“测试通过”没有说明接受了什么风险。重要决定至少记录决定内容、依据、范围、剩余风险、责任人和下一步。

范围必须限定到实际审查的维度。接受目录结构不等于接受其中的技术事实；接受技术解释不等于接受工程结果或发布风险。一个产物可以同时处于“结构已接受、事实待核、结果未验证”的状态。

## 6. 责任条件与可检查证据

| 对象 | 审查需要留下或能够展示的证据 |
|---|---|
| 理解 | 责任人能说明目标、关键逻辑、证据边界、主要风险和剩余未知量 |
| 控制 | 责任人实际能够编辑、拒绝、回退、暂停或把判断转交给合适的人 |
| 决定 | 决定内容、适用范围、责任、剩余风险和后续动作得到明确记录 |
| 审查依据（支持项） | 可访问的原始材料、diff、测试、日志、来源和独立检查 |

审查依据为理解和决定提供基础，但不是与前三项同类的第四项责任条件；拥有材料也不等于实际理解。任一责任条件缺失时，不能仅凭流程中出现过人推断审查已经完成。以上只规定可检查的结果，不要求固定字段名、文件、界面或状态机。

## 7. 高影响决定的额外理解核验

高影响决定可以增加独立于普通浏览和批准动作的理解核验。一种可替换的实现是：Agent、责任人或其他系统整理审查材料，责任人在不可逆承诺获得授权前，用自己的语言说明其理解。它不是所有任务必须按序经过的固定状态，也不要求由 Agent 独自判定是否通过。

审查材料可以包含：

- 当前需要决定什么，为什么必须现在决定；
- 可选方案、Agent 建议及主要取舍；
- 关键事实、假设、证据和未决问题；
- 主要风险、不可逆后果和影响对象；
- 哪些新证据会改变当前建议；
- 批准后系统将执行的具体动作。

确认问题应检查理解，避免只问“你理解了吗”。例如：

1. 请用自己的话说明当前决定及其目的；
2. 最重要的风险和不可逆后果是什么；
3. 还有哪些可选方案，为什么当前方案获得推荐；
4. 哪项事实仍是关键假设；
5. 出现什么新证据时应暂停或改变决定。

理解与同意必须分开。责任人反对 Agent 建议、使用不同术语或提出新的合理取舍，不能被判定为“不理解”。

Agent 同时担任提案者、解释者和唯一考官时，存在相关失败风险。高影响场景中的理解标准应引用原始证据、独立规则、领域专家或确定性检查。Agent 可以检查回答是否覆盖关键内容，不能垄断“什么意见才合理”的定义。

## 8. 竞争性解释

审查失败不一定来自责任条件缺失，还可能来自：

1. **领域能力不足**：责任人没有判断关键事实所需的专业知识；
2. **证据不可得**：原始数据、日志、代码或决策背景无法访问；
3. **自动化偏见**：流畅表达和默认推荐提高了接受倾向；
4. **时间与注意力不足**：审查深度超过责任人能够投入的资源；
5. **责任分散**：批准者、领域专家、实施者和受影响者并非同一人；
6. **虚假可控**：界面允许编辑，但修改成本高到实际上只能接受默认结果；
7. **相关失败**：人和 Agent 共享同一错误表征、材料或评价标准；
8. **形式化过载**：审查材料、复述问题和状态记录占用注意力，却没有改变判断。

因此，不能把“增加一个人”“增加解释”或“增加确认题”当作统一修复。审查强度应由影响、歧义、不可逆性、证据缺口和责任结构决定。

## 9. 适用边界与反例

- 目标固定、改动可逆且有确定性检查的低风险中间产物，可以抽样或自动验收；
- 探索性写作没有唯一 Oracle，审查更依赖约束满足、表达控制和人工选择；
- 高影响代码即使测试通过，也仍需审查意图、权限、维护边界和未覆盖风险；
- 人工审查会受到疲劳、锚定、组织压力和领域盲区影响，增加人不自动提高质量；
- 解释可能降低核查成本，也可能提高错误建议的可信度；
- 责任人不必亲自完成所有专业验证，但必须知道哪些判断委托给了谁，以及自己最终接受什么；
- 对即时、低风险和可撤销的决定使用完整的额外理解核验，可能降低真实任务成功率。

可能显著削弱本文判断的证据包括：在控制任务难度、审查者能力和时间成本后，具备理解、控制和明确决策条件的审查没有减少错误承诺、过度依赖或虚假完成，反而稳定降低结果质量。

## 10. 对日常 Agent 使用的意义

1. 在交付前展示原始来源、完整 diff、测试和实际制品，不只展示摘要；
2. 要求责任人能够复述目标、关键逻辑、证据边界和主要风险；
3. 保留直接编辑、拒绝、回退、暂停和升级的能力；
4. 把理解与同意分开，允许充分理解后的反对；
5. 明确记录接受、要求修订、拒绝或转交中的实际决定及其范围；具体名称可映射到现有流程；
6. 记录决定覆盖的维度和范围，不使用全局“已审查”掩盖局部未知；
7. 高影响场景引入独立证据、领域专家或确定性检查，避免 Agent 自己定义并通过全部标准；
8. 低风险场景使用最小充分审查，避免把责任控制变成形式负担。

这些要求描述责任条件，不要求固定按钮、字段结构、状态机或一个名为 Reviewer 的 Agent，也不能通过增加相同上下文下的第二个模型来替代人类责任。

## 11. 待区分的问题

| 决策对象 | 竞争解释 | 足以改变判断的证据 |
|---|---|---|
| 理解测量 | 复述关键逻辑能预测真实理解，或主要测到记忆、表达能力和迎合 | 比较复述、反事实预测、错误定位和新情境迁移对后续决策正确率的预测力 |
| 真实控制 | 直接编辑与拒绝权能纠正错误，或交互成本把生产负担转嫁给责任人并导致形式接受 | 在相同产物与审查者条件下比较错误修正、拒绝质量、审查时间、放弃率和默认接受率 |
| 审查净收益 | 三项责任条件降低错误承诺和过度依赖，或只增加延迟并降低有效自动化 | 按任务影响、复杂度和可逆性分层，对照最终决策错误、遗漏风险、人工时间和总任务成功率 |
| 分布式责任 | 单一责任人能整合决定，或领域专家、实施者和受影响者必须分别拥有不同否决权 | 对真实交接与事故追踪决定来源、信息缺口、责任漂移和错误拦截位置 |
| 额外核验阈值 | 影响或不可逆性足以触发理解核验，或证据缺口与审查者能力才是主要预测变量 | 比较不同触发策略在分层任务上的漏检、误触发、审查成本和不可逆错误 |
| 证据独立性 | 增加第二意见已经足够，或必须改变材料、评价标准与失败路径才能降低相关错误 | 分别改变审查者、模型、原始材料和 Oracle 的共享程度，测量相关误判与新增成本 |
