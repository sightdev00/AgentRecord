# 贡献规范

本仓库接受问题求解经验，不接受单纯的信息搬运。

## 提交前先判断内容属于哪里

| 内容 | 目录 |
|---|---|
| 尚未核实的线索、链接、想法 | `inbox/` |
| 单次真实问题的完整求解过程 | `cases/` |
| 两个以上案例共同支持的机制 | `patterns/` |
| 在明确边界内采用的实践原则 | `decisions/` |
| 用于区分、证伪或回归的实验 | `experiments/` |
| 基础理论与概念辨析 | `foundations/` |

不要按“论文、仓库、博客、Prompt、Skill”分类。载体不是知识结构。

## 最小要求

- 从 `_meta/templates/` 选择模板；
- 事实、推断、假设、决策分开写；
- 原始证据使用稳定路径、URL、commit 或日志片段定位；
- 至少写出一个替代解释或反例；
- 明确什么结果会推翻当前判断；
- 明确适用边界、版本和失效条件；
- 未验证内容使用 `draft`，不要包装成结论。

## 修改已有结论

新证据与旧结论冲突时：

1. 不覆盖原结论的历史语境；
2. 把旧文状态改为 `superseded`；
3. 使用 `superseded_by` 指向新文；
4. 在新文中说明是哪条证据导致修订。

## Commit

一次提交完成一个知识主题，提交信息说明“形成或修订了什么认识”，不要按文件逐个提交。
