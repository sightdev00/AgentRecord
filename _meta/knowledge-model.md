# 知识模型

AgentRecord 管理的不是“内容”，而是判断从哪里来、为什么成立、何时失效。

## 一、五种正式资产

| 资产 | 回答的问题 | 最低证据门槛 | 不能替代它的东西 |
|---|---|---|---|
| Foundation | 应用什么基础概念理解问题 | 原始理论来源与概念边界 | 术语拼盘 |
| Case | 一次真实问题是怎样被解决或误解的 | 可定位的事实、过程和结果 | 成功故事、聊天摘要 |
| Pattern | 什么机制跨案例重复出现 | 至少两个独立案例，或理论加真实案例 | 单一案例的感想 |
| Decision | 当前在什么范围内采用什么做法 | 依据、边界、反转条件和责任 | 无条件“最佳实践” |
| Experiment | 如何区分假设或检验模式 | 可复现方法、Oracle 和原始结果 | Agent 自我评价 |

`inbox/` 不是正式资产，只是等待处理的临时入口。

## 二、知识形成过程

### 1. Capture

只保存原始问题、异常、证据指针和不确定性，不急着总结。

### 2. Reconstruct

把材料写成 Case：恢复当时的目标、约束、初始表征、竞争假设、关键实验和决策点。

### 3. Abstract

比较多个 Case，只抽取因果结构相同的部分。表面相似不算模式。

### 4. Commit

当模式足以支持行动时写 Decision。Decision 必须说明适用范围、保留异议和撤销触发器。

### 5. Challenge

通过 Experiment 主动寻找反例、边界和回归。实验失败不是废料，它会改变资产状态。

### 6. Revise

保留旧结论，建立 `supersedes / superseded_by` 关系。知识演化应可追溯。

## 三、证据与判断分离

正文中的关键陈述使用以下标记：

- **观察**：直接来自日志、代码、原始资料或可重复测量；
- **推断**：根据观察作出的解释；
- **假设**：尚待区分的解释；
- **决策**：在风险和证据约束下选择的行动；
- **结果**：由预先定义的 Oracle 得出的验收结果。

没有来源的陈述不能从“假设”直接升级成“结果”。

## 四、成熟度状态

```text
draft → tested → replicated → bounded
   └──────────────→ superseded
```

- `draft`：结构完整，但关键证据仍缺失；
- `tested`：至少一次真实测试支持；
- `replicated`：在不同案例或环境再次成立；
- `bounded`：已经明确主要适用范围和失效条件；
- `superseded`：被后续证据替代，仍保留用于追溯。

状态不能自动递增。文字更完整、引用更多、模型更强，都不构成升级理由。

## 五、从 Case 到 Pattern 的门

只有同时满足以下条件，才建立 Pattern：

- 至少两个来源相对独立的 Case；
- 对齐的是因果关系，不只是相同工具或相似报错；
- 记录至少一个不符合该模式的反例；
- 说明模式能预测什么；
- 说明什么新证据会使模式失效。

## 六、从 Pattern 到 Decision 的门

Decision 不是“这是真的”，而是“在当前约束下，采用它的收益高于风险”。至少记录：

- 决策范围；
- 所依据的 Pattern 和 Case；
- 未解决的不确定性；
- 被放弃的方案；
- 回滚或复议触发器；
- 验收责任和时间。

## 七、索引原则

主要链接写在各目录 README 中。暂不引入数据库、向量索引或自动知识图谱；只有当真实检索失败案例证明手工索引不足时，再增加工具。
