# AgentRecord

> 关于 Agent 基础问题、稳定机制与认识修订的长期思考记录。

[English summary](./README.en.md)

## 长期目标

> 根据我的案例描述，完善Agent的使用经验，但又不会受制于风靡一时注定退出历史舞台的工具框架。

本节是仓库当前长期方向的权威表述。方向改变时直接修订本节；Codex 任务状态、执行计划和临时进度不进入仓库。

“根据案例描述”表示用案例定位问题、反例和待核证据，不表示把叙述直接当成事实或通用原则。只有可定位的案例制品及其对既有判断、边界或行动的影响，才进入负责该问题的权威分析。

Agent 工具、框架和产品变化很快。这个仓库不追踪它们的数量，也不把 Prompt、Skill、教程或项目案例当作长期资产；它只保留能够跨工具继续成立、并且已经形成独立判断的分析。

## 唯一职责

AgentRecord 研究 Agent 本身，例如：

- Agent 如何表征问题，以及错误表征怎样限制后续搜索；
- 搜索为什么会过早收敛；
- 假设如何形成、竞争、被证伪或被修订；
- 证据不足的判断为什么会过早升级为行动；
- 执行、验收和记忆写入为什么需要相互制约；
- 用户如何受到自动化偏见、过度依赖和认知卸载影响。

## 不收录

- Agent 工具、框架、热门仓库和新闻清单；
- 安装配置、使用教程、Prompt 或 Skill 收藏；
- 视觉算法等领域工程案例及其代码、实验和实施计划；
- 尚未形成独立判断的论文、帖子或聊天摘要；
- 为显得系统而扩建的目录、模板和流程。

外部论文、项目和工程案例只能作为分析中的证据指针。原始过程和制品保留在其所属仓库，不复制到这里。

## 配套工程仓库

[AgentWorkbench](https://github.com/sightdev00/AgentWorkbench) 是本项目的工程化配套仓库，负责保存我自己的工程经验、外部 Agent 工程案例、复现、实验和可执行实现。两个仓库组成一个整体，但不维护重复权威：

- AgentRecord 维护跨工具成立的基础问题、机制、证据强度和责任边界；
- AgentWorkbench 维护具体实现事实、适配过程、测试结果和失败记录；
- 工程观察只有在改变本仓库的判断、证据强度、适用边界或日常行动时才回流；
- AgentRecord 通过固定 commit、版本或实验指针引用工程证据，不复制其过程和实现。

AgentWorkbench 当前处于私有孵化阶段。它公开以前，私有制品不能成为 AgentRecord 公开结论的唯一证据；本仓库只保留不会泄露敏感信息的职责连接、证据角色和可公开来源。

## 准入标准

一篇新分析至少应：

1. 讨论 Agent 本身的基础问题，而非某个领域的具体实现；
2. 区分事实、结构类比、推断、假设和当前结论；
3. 使用可定位的来源，并主动处理反证或竞争解释；
4. 说明适用边界、仍未知之处和可能推翻结论的证据；
5. 对日常使用 Agent 产生明确但不过度扩张的含义；
6. 把具体工具和实现限定为可替换证据；删除产品名后，核心问题与判断仍能成立。

一次对话或任务只触发经验筛选，不保证产生仓库修改。新证据属于同一问题时直接修订权威分析；多条支持来源要说明共同模型、数据、基准、评价器或组织依赖，不能按数量自动提高可信度。

分析被修订、相邻问题新增或权威关系变化时，同时复核它是否仍拥有独立问题、有效证据和会改变实际决定的含义。失去这些条件时，先提出精确的合并、链接、索引和删除清单；获得所需的结构确认后，再合并有效内容并删除旧文章。证据不足但仍影响行动的独立问题则保留并收窄判断。Git 历史保存被取代的文字，不另设成熟度标签、归档目录或资产状态系统。

主动研究只优先处理能够区分当前未解决问题并改变行动、授权、验收或保留决定的证据缺口；新颖度和流行度不构成优先级。详细规则见[写作与证据规范](./_meta/writing-guide.md)。
