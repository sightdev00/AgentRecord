# Repository instructions for agents

This repository accumulates problem-solving knowledge, not tool inventories.

When adding or revising content:

1. Start from a real question, failure, decision or experiment.
2. Classify the artifact by its epistemic role: foundation, case, pattern, decision or experiment.
3. Keep observations, inferences, hypotheses and decisions separate.
4. Preserve competing explanations until discriminating evidence is recorded.
5. Search for counterevidence before upgrading a claim.
6. Do not treat model self-review as independent verification.
7. Record provenance, version, validity boundary and supersession.
8. Do not create a new prompt, skill, adapter or tool directory unless a validated case demonstrates the need.
9. Do not inflate one case into a universal pattern.
10. Prefer one clear thematic commit over many file-by-file commits.

Before declaring work complete, run `_meta/check.sh` and report any remaining warnings.
